### 最初の学習後に決めること

- **TRAINにも適合しない**：ラベル・勾配・最適化を確認し、その後に判断層容量を比較する。
- **TRAINは良いが未知条件で崩れる**：独立した教師信号の多様性と対応付けを優先する。
- **正解状態なら解け、実入力で崩れる**：凍結特徴と接続のどちらで情報を失うかを限定診断する。
- **時間・関係だけで崩れる**：対象や時刻を比較する小型の処理を候補にする。
- **正しい共同入力と取り違え入力が同じ**：ラベルの相補性・同期・入力利用を確認する。

一段cross-attentionが全課題に十分とは決めつけない。一方で、未学習の段階から容量不足と
判断して大型化もしない。必要なら小さい専門処理や複数段の読み出しを比較し、全推論部品を
200Mに数える。「一つの製品候補」と「一つの判断層に全処理を押し込む」は同じ要件ではない。

## 1. 結論

**現行196.25M構成を最初の統合比較基準として学習・評価する。その結果で改善箇所を一つ決める。**

今の最大の空白は、同じ実行候補で条件理解・知覚・時間判断・共同判断を測った結果がないこと。
これまでの診断には意味があるが、別モデル・別タスクの良い数字を集めても製品の品質は判定できない。
次の作業は入力の不整合を解消し、基準学習と共通評価表を完成させることに集中する。

目標は量子化前の全推論パラメータ200M以下、text/image/audio/video、候補確率のJSON出力。
事前定義した各必須タスクで95%以上、98%を目指す。センサーは任意。
自然言語の条件、未知の候補、時間・共同判断を固定分類へ置き換えない。
未定義のあらゆる問題に95–98%を保証できるという根拠は、現在ない。

## 3. アーキテクチャと出力

主経路は既存Encoderの再利用（Path A）。画像と動画は共有VideoPrism、言語はDeBERTa、
音声はWhisper encoderとEfficientATを用い、最初は凍結したまま共通判断層を学習する。
一度抽出した観測特徴を、異なる条件と候補から読み出す。

JSONは通常のプログラムで構成する。排他的な多択はsoftmax、独立したyes/no群は各問の確率として
意味を分ける。二択も多択も同じ製品APIに含められる。現在の実装は多択経路なので、独立二値群や
質問文を使わない固定タスクの経路を実装済みとは扱わない。確率出力だけで校正済みとも呼ばない。

「同じ候補で評価する」は、全Encoder・接続・判断層を含む一つの版を固定するという意味。
一つのTransformer／一つの判断層への統一そのものは製品要件にしない。
課題別の小さい枝が有効なら比較できるが、全てを200Mに数え、未知条件にも対応する必要がある。

現構成の残余は3,745,126パラメータ。現在の判断層を置き換える場合、他部品が同じなら
判断部分全体の上限は4,634,471。追加層の余地はあるが、容量不足はまだ証明されていない。
現在の一段のcross-attentionは基準実装であり、関係・時間推論に十分という保証ではない。

凍結VideoPrism＋軽量読出しには[公式実装](https://github.com/google-deepmind/videoprism)の裏付けがある。
条件付き読出しの参考には[Perceiver IO](https://arxiv.org/abs/2107.14795)がある。
これらは方式の参考であり、本候補の95–98%達成を裏付けるものではない。

| 4 | 保存予測と事前固定した対照から主な失敗を選ぶ | 下表に基づく一つの改善比較。新しいモデル・loss・データを同時に変更しない |
| 5 | 品質と保持が成立した構成を確認し、校正・圧縮・最終監査へ進む | 独立校正、実機8/4-bit比較、実package容量・p50/p95・RAM/VRAM、凍結後の最終監査 |

初回runの更新数は、この戦略文書で推測して決めない。実samplerのunique coverageと実測throughputから
最大予算・評価間隔を決め、学習開始前に固定する。後から都合よく延長しない。
現在のC:空きは約5.05GB。全AV特徴の無制限な複製は避け、同じ前処理を保つ逐次読込・容量制限付き
cacheを検討する。保存容量不足を理由にframe数や入力の意味を黙って変えない。

共同判断用データの不足を単独入力の基準学習まで無期限に止める理由にはしない。
その場合は共同判断を明確に未測定として残し、単独入力の結果でR2全体を完了扱いにしない。
共同判断には既存の権利確認済み対応付けデータを先に使い、実場面への汎化は別に検証する。

## 5. 評価を設計の中心にする

| 必須能力 | 維持する評価 |
|---|---|
| 条件理解 | 同じ観測への異なる質問、否定・除外・比較、未知の言い回し／候補。ペア両問正解率 |
| 画像 | 属性・個数・関係。正解状態を使った診断と実画像判断を区別 |
| 音声 | 発話と環境音を分離。語彙・音韻・長さが近い候補、独立話者／収録環境 |
| 動画 | 前後・状態変化・対象追跡。時間順変更と動画取り違えの対照 |
| 共同入力 | 両入力が必要なラベル設計。単独入力、同一モデルの欠落／取り違え、必要なら同予算の単独学習対照 |
| 横断条件 | 候補順の入替、質問のみ、未知場面、言語範囲、入力欠落、校正、最弱課題 |

同一モデルから一方の入力を消す対照だけでは、最適化された単独モデルとの比較の代わりにならない。
逆に、別の単独モデルより高得点でも、正しい相手入力を使った証拠にはならない。両方を区別する。

既に何度も観測したvalidationは開発・回帰用とする。新しい開発評価は独立した場面・話者・
意味構成を先に固定し、最終auditは開かない。テンプレート生成だけで自由な自然言語を代表させない。
日本語・自然画像・自由発話は、既存データで未確認ならそのまま未確認と記録する。

STARSS23のbellには学習正例がなく、validationのwater-tapには正例がない。
これは反復学習では解消しない。許可済みの追加教師信号を準備するか、当該能力を未達と残す。
難しいクラスを削除したり、負例多数のAccuracyだけで合格させたりしない。

過去47区分の保持ゲートと不採用判定は変更しない。新しい統合実験では、必須能力・許容低下・
独立単位の区間推定・選択規則を先に固定する。研究上の改善、既存能力の保持、製品95–98%達成は
別判定にする。棄権で得た条件付き精度は全件Accuracyと回答率を併記する。

## 6. 失敗時の分岐と打切り

| 測定結果 | 次に一つだけ検証すること |
|---|---|
| 正しい状態でも条件を取り違える | 条件と候補の対応付け／言語教師信号。視覚Encoderの交換は根拠にならない |
| 正しい状態なら解けるが実入力では解けない | 知覚特徴に必要情報が残るか、局所・時間情報を接続で失っていないか |
| 静止属性は解けるが前後・追跡で失敗する | 対象と時刻を比較できる小さい接続層。frame数増加だけを原因と決めない |
| TRAINでも学習が成立しない | ラベル・勾配・最適化を確認後、読出し容量の限定比較 |
| TRAINは改善し未見条件が悪化する | データの意味的多様性／分割／過学習。単なるstep増加はしない |
| 正しいAVと取り違えAVが同じ | 課題の相補性・同期・入力利用を確認。融合層を大きくする前に原因を切り分ける |

追加診断には「どの結果なら何を変えるか」を必ず付ける。実装判断が変わらない再診断は増やさない。
閉じた文面・係数・seed探索、根拠のない大きな教師への回帰、QAT／Recoveryの再開、重み統合、
必須でないセンサー追加は当面の主作業にしない。Path B/CはAに実測の限界や費用問題が出た時だけ開く。
凍結Encoderも永久条件ではないが、限定適応は不足箇所と学習費用を測定してから比較する。

次の進捗報告の中心は、**同じ候補の全タスク表、最弱課題、保持、学習曲線、次に変える一箇所**。
テスト数・cache数・文書数を品質進捗の代用にしない。
