# 次の開発戦略：条件を理解し、実入力に基づいて判断する

2026-10-15。ユーザーからの「これまでを整理し、どう進めるか戦略を組む」への実行方針。
全実験の根拠と履歴は[戦略・証拠集](STRATEGY_20261015.md)に残す。

## 1. 作るものを固定する

**量子化前の全常駐パラメーターが200M以下で、テキスト・画像・音声・動画の観測と条件から、
提示された候補の確率を返すモデル。** 同じ観測表現を複数の質問に再利用する。センサーは任意。
条件は任意とし、非テキスト入力だけから判断する経路も維持する。発話／テキストの質問や、
必須の文字起こしを全モダリティの入口にはしない。

出力はJSON。候補IDと確率を通常のコードで整形し、文章生成用decoderは必須にしない。
二択も多択も同じ候補採点のインターフェースで扱う。独立した複数のyes/noと、排他的な多択は区別する。
目標は、事前定義した各必須課題で95%以上、98%を目指すこと。四モダリティ平均への置換はしない。
任意の未定義問題に95–98%を保証できるとは主張しない。

## 2. 現在地と優先課題

| 分かったこと | 判断 |
|---|---|
| 生入力処理、特徴再利用、JSON、save/reloadは動く | 既存基盤を再利用する |
| 195.42Mの構成要素を同時常駐できた | サイズの見通しはある。統合済み高品質製品の証明ではない |
| 限定した条件対応は100%まで学習できた | 学習可能性はある。ただし未知の指示・候補表現への転移が弱い |
| 指示の多様化は一部の転移を改善したが、除外理解と保持に失敗 | 同じ文面の追加や学習延長を続けず、条件の意味に対する教師信号を変える |
| 正しい構造化状態でも誤る | まず判断側を改善する。全encoderの増強が必要とは結論しない |
| AVで99%超でも映像を取り違えて答えが変わらない例があった | 高得点だけでは両入力を利用した証拠にならない |
| 大きい教師も固定したラベル出力方式で不安定だった | 大きさだけを理由に蒸留せず、能力と読出しを別に検証する |

現在、製品目標は未達。最優先は**未知の条件に対する意味理解と、既存能力を維持した転移**。
次に、実入力の情報保持、動画の時間関係、複数入力の共同利用を同じ判断課題で測る。

## 3. 採用する構成

既存の共有画像／動画encoder、小型の発話・環境音経路、条件と候補を読む小型言語経路、
軽量Decision中核を組み合わせるArchitecture Aを主線とする。各候補に同じ採点器を適用し、
候補IDと表示順に依存しない構造を保つ。ただし順序安定性だけで条件の意味理解が成立するわけではない。

現時点の設計予算は約175.535M、約24.465Mの余裕を持つ。ただし、Whisperをencoderだけで使うことや
言語経路の統合は品質未検証の設計仮説であり、完成品の計測値ではない。
最終判定では埋め込み・投影・融合・音声／映像経路を含む、実際にロードする全重みを数える。

Shared Transformer/Lensや重み統合は、Architecture Aで診断した品質・費用の問題を解決できる場合に比較する。
既存の互換性・ライセンス監査を使い、手法を組み込むこと自体を目標にしない。

## 4. 次の三つの成果物

### A. 条件理解の学習契約と、一つの比較実験

- 同じ状態に対して、肯定・除外・否定・比較で正解が変わる対照を作る。
- 状態、構文系列、候補説明の組合せをTRAINと検証で分離する。既に見た診断は回帰用として残す。
- 正解は検算できるラベルを基準にし、失敗した教師の回答で置き換えない。
- 次の候補は、**条件が変わったときの候補確率の変化を直接教える対照的な教師信号**。
  同一データ・初期重み・保持データ・計算予算で、通常の正解ラベル学習との一要因比較にする。
  損失、例数、予算、評価数、採否条件は実装前に固定する。この文書はその学習を実行した報告ではない。
- 評価するのは各条件のAccuracy/NLL/Brier/ECE、条件ペアの両問正答、既存能力保持。
  同じ観測済み集合で係数や文面を探し続けない。

この比較でも未使用の構文へ移らない場合、同じ小型モデルの微調整を反復しない。
独立した言語能力評価に基づき、200M全体予算内で言語表現の配分を一度見直す。
教師方式の追加比較を行う場合も、この同じ独立契約を先に決め、良いラベルや文面を探す探索に戻らない。

### B. 正しい状態からの判断と、実入力からの判断を接続する

同じ質問・候補に対して、診断用の正しい状態と、実画像／音声／動画から得た表現を比較する。
正しい状態でも失敗する部分と、知覚で情報を落とす部分を分ける。
正解注釈を製品入力へ渡した精度を実入力精度として報告しない。

画像では対象・数・関係、音声では発話条件とイベント、動画では順序と状態変化を扱う。
訓練場面と評価場面を独立させ、局所／時間情報の不足が確認できた経路だけを小さく適応する。
全encoderを恒久的に凍結するとも、一度に全て学習するとも決めない。

### C. 四モダリティの一つの製品候補にする

入力取り違え・片側除去・時間順序反転の対照を含め、共同判断に各入力が必要か確認する。
公開データの利用許可とscene/speaker/source分離を維持し、センサーの追加を完成条件にしない。
全入力からJSONまでを同じ実行系で測り、全常駐数・容量・遅延・メモリ・校正をまとめる。

高精度版の品質が成立してから8bit、必要なら4bitを比較する。ternaryはその後の別比較。
200M以下は量子化前の重み数、200MB以下は別のパッケージ目標として管理する。
最終監査は構成と選択規則を固定した後に行う。

## 5. 続ける条件・打ち切る条件

- 一度に学習する仮説は一つ。追加seedは有望な構成の再現確認に限る。
- 次の研究候補の暫定前進基準は、最弱の対象課題で3ポイント以上改善、状態単位の不確かさも改善を支持、
  他の必須課題を1ポイント超損なわないこと。校正と保持の具体的基準も実験前に固定する。
  この基準を製品95–98%の合格条件には使わない。
- 同じ主要仮説の二つの事前比較で有用性が出なければ、その経路を閉じる。
  新しいデータ／表現など原因を変える根拠があるときだけ別仮説へ進む。
- 以後の進捗は「独立課題の品質」「最弱課題」「保持」「全常駐サイズ」で判断する。
  テスト件数・ロード成功・レポート数で品質進捗を代用しない。
- ローカルGPU、独立出力先、旧成果物保全を維持。有料計算・既存稼働プロセスへの介入は別承認。

## 6. 今回の追加診断

表示順とラベル割当の二要因比較は実行済み。TRAIN64状態・384問×4条件の1,536提示。
属性除外は、元81.25%、表示順のみ反転59.38%、割当のみ反転74.22%、両方反転42.97%。
数値判断は全条件52.73–54.69%。過去768出力とlogit完全一致、別processの事前指定48出力も一致した。
[全指標・不確かさ・資源・ハッシュ](R2_TEACHER_LABEL_FACTORIAL_RESULTS_20261015.md)。

表示順の影響が大きく、ラベル割当も影響する。一方、数値判断には今回の変更による改善を確認できない。
固定教師のこの出力方式をそのまま蒸留に使わない。studentは既に候補ごとの採点を使うため、
教師の順序問題を直すこととstudentの条件理解改善を混同しない。
この診断一回でラベル／表示方法の探索を閉じ、上記Aの独立した学習契約へ進む。
