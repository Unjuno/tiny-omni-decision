# Independent decision supervision contract v1

## Purpose and scope

Freeze the next strategy deliverable before choosing another model, architecture,
loss, optimizer or training budget. This is a CPU corpus/selection implementation,
not a model-quality experiment. Zero native media, model loads or optimizer steps.
The four-modality product, <=200M resident parameters before quantization,
per-required-task95–98%, calibrated probabilities/JSON, temporal/joint/OOD gates
remain unmet. Programmatic structured states are diagnostic/learning inputs,
not substitutes for future native image/audio/video evaluation.

The previous fixed factorization and conditional-contrast screens are closed.
No prompt, seed, temperature or budget search on their observed questions.
This contract defines new independently grouped development data and preserves
known original-task regression data. It does not select MiniLM or DeBERTa.

Original typed decisions include plain prose as well as JSON states. Preserve
their bytes and use whitespace-normalized text identity for prose; do not
require every legacy observation to parse as JSON.

## Frozen inputs and partitions

Configuration: `configs/pretrained_reuse/decision_supervision_v1.json`.
Primary seed17; named deterministic namespace for numeric generation and hash
ordering for binding states. All23 explicit local inputs are SHA-256 pinned.
No recursive artifact discovery or sealed audit reads by the builder.

Binding exclusions: the previous frozen factorization exclusion manifest plus
its32 observed states, totaling7,612 states. Select unused combinations from the
same10-by-10-by-10-by-10 attribute vocabulary. This measures composition with
known vocabulary, not unseen objects, natural language or native perception.

Numeric exclusions:17 declared historical TRAIN/development payloads, including
context robustness and text-prefix factorial. Canonical identity removes item
labels/order, resolves cost/price aliases, subtracts the global minimum and
divides by the exact integer GCD. Thus positive global affine transformations
stay in the same class. Independent review found3,328 known classes; assert that
count before generating. This does not claim invariance to arbitrary nonlinear
or independently per-column transformations.

| Partition | Binding states/questions | Numeric states/questions | Total questions |
| --- | ---: | ---: | ---: |
| train |512 /8,192 |1,024 /8,192 |16,384 |
| validation |128 /1,024 |256 /2,048 |3,072 |
| development transfer |256 /2,048 |256 /2,048 |4,096 |

Binding: four requested fields and four training syntax families per state.
Validation and transfer each use two different literal templates per field,
disjoint from training and each other. All40 candidate values are present in
every question; no pruning to the requested field. Within a state, condition
changes keep identical candidates/order. Hash-shuffled candidate order is
independent of the requested field and deterministic.

Numeric: four entities with integer cost/risk/time in1–199, no per-column ties.
All eight queries remain together: each field's minimum and maximum, number
of items with risk<=threshold, and cheapest eligible item (or none). Threshold
is deterministically sampled from0–200 and included in the request. Six
extremum tasks retain four candidates; counting and constrained selection
retain five. This preserves the earlier numeric task widths. Time is a recorded
numeric field here; this is not evidence of video temporal understanding.

All states and all their questions belong to exactly one partition. Fail on
duplicate IDs, missing state questions, normalized public-content overlap,
canonical state overlap, or collision with declared previously observed states.
The exclusion inventory is explicitly bounded to the pinned sources; it is not
a claim to have searched every arbitrary file or all pretraining data.

## Public inputs and private supervision

Only `state`, `question`, `options`, `option_ids` cross the `public_example`
inference boundary. IDs, task/family, split, rule, target and supervision are
private data/metric metadata. Poisoned private fields must not affect rendering.

Each binding question has per-candidate labels:

- `fact_true`: four values actually recorded in the state;
- `request_relevant`: ten values of the requested property;
- `correct`: their one-element intersection.

This explicitly distinguishes the three true-but-irrelevant values from the
one correct response. Numeric correct labels are computed exactly from the
record and request; fact/relevance arrays are null, not invented binary labels.
They are deliberately separate tasks, not an assertion that numeric reasoning
is reducible to field routing. Labels are program-derived, not generated by a
teacher that failed the prior capability checks.

No model inference has been run on these validation/transfer questions. Corpus
construction necessarily validates their labels. The small authored template
families do not establish broad language independence or a blind product audit.

## Existing capabilities and isolation

Reuse the exact existing mixed replay TRAIN file:1,024 original typed-decision
questions plus1,024 curriculum questions. Keep it separate from fresh train data
and report it as reused coverage, never as new unique examples.

Preserve byte-identical copies of original, curriculum and old binding validation
files. Concatenate their unchanged JSONL bytes for the retention loader. These
are already-observed regression sets, never a new generalization benchmark.
Recheck train/validation state identity and IDs, and exclude their states from
all new partitions. Original typed data retains its prior ALLOW admission;
no new external data or media is ingested. Programmatic data uses repository
code and the existing permitted taxonomy; no new license assumption is made.

`load_for_fit` accepts only train, validation, retention_train and
retention_validation. It checks the caller-supplied immutable corpus manifest
hash, payload hash, terminal status and partition membership. It rejects transfer
before opening files. Post-selection transfer evaluation requires a separate
frozen runner/config/checkpoint contract; this step does not provide that runner.
No sealed audit is created or read here; existing sealed audits remain untouched.

## Selection policy, before any fit

Save exact required slice counts in `selection-schema.json`: new binding
family-by-field, all six numeric field-by-direction tasks plus count and filter;
legacy source/task slices, with legacy curriculum extrema also separated by
field/direction. Original typed-data slices retain their existing task types.
Do not silently omit slices, shrink evaluation or select on sample-weighted
aggregate alone. Metrics must include Accuracy/NLL/Brier/ECE and exact counts.
Only validation-purpose records are accepted; transfer/audit selection fails.

Choose a prospective frozen model initialization before its first evaluation;
its step0 metrics form the reference on these same IDs/preprocessing. Do not
choose whichever old baseline makes a candidate look better. For every required
slice, retain the prior safeguards: Accuracy loss<=.01, NLL increase<=.02,
Brier increase<=.01 and ECE increase<=.02. Nonfinite candidate metrics are
ineligible; impossible finite metric ranges and changed counts are errors.
Choose minimum equal-slice macro NLL among eligible checkpoints **including
step0**, earliest step for exact ties. Always retain step0 and final separately.
Optimizer/model/sample schedule and evaluation cadence remain unfrozen and
must be specified separately before starting any training.

Research advancement additionally requires >=.03 improvement in the minimum
Accuracy across the16 predefined NEW validation slices (not a retrospectively
chosen favorable task), alongside all retention safeguards. For uncertainty,
paired bootstrap whole states, separately within binding/numeric cohorts,
10,000 replicates, seed17, percentile95% interval with linear interpolation;
recompute the minimum over all16 slices in each replicate and require its
difference lower bound>0. Resample all questions of a state together. Templates
are fixed and not resampled. This development/selection statistic cannot prove
95–98% product quality or unbiased blind generalization. Implement/validate the
uncertainty calculation in the eventual experiment runner before any fit.
