# R2 MiniWoB++ Screen-Action Preflight (2026-11-12)

## Disposition

The pinned MiniWoB++ `click-color-v1` task now has a reproducible **screen-only**
development corpus and integrity checks. This is a synthetic UI action task; it
does not measure broad image understanding, multimodal fusion, physical action,
or product quality. It advances only the R2 M-0/M-1 screen-only data gate.

No pretrained feature was extracted, no model was fit or scored, and no
Accuracy/NLL/Brier/ECE was computed. R2 M-1 quality and the separate R2 M-2
audio/video/sensor fusion gate remain open. The local development validation
corpus is not a sealed audit set.

## Collector corrections

The initial text-target collector looked for `#query-color` in MiniWoB's
`obs["dom_elements"]`. That observation prunes empty visual DIV nodes, so the
target swatch could be rendered while absent from the returned DOM. Some
examples labelled text-only therefore had an additional visible target cue.
Those old samples are retained, marked invalid for that intended task, and were
not used for fitting or model evaluation.

The apparent text/screenshot color mismatch was also a false alarm: the yellow
pixels sampled were the UI's yellow query-panel background. Direct browser
inspection showed the rendered swatch, task target, and matching candidate had
the same color. The corrected collector determines task variant from a live
browser-side DOM query, then independently checks screenshot pixels.

A second issue affected the first three JSONL smoke manifests and full corpus
attempt-01: Windows `Path.write_text()` converted LF line endings to CRLF after
the JSONL digest was computed. The declared digest consequently differed from
the stored bytes. All such files remain untouched with external corrigenda;
they are not authoritative corpora. The collector now writes canonical JSONL
as bytes and hashes the file contents. A regression test covers this Windows
newline failure.
